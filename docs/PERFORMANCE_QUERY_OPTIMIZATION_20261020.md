# 绩效长区间查询优化

日期：2026-10-20，Asia/Shanghai。生产环境，仅优化读取，不重算或修订业务账表。

## 原因

1. 基准曲线按每一个交易日串行向 Meridian 请求 14:55..15:00 分钟线。债享5号 `20260101..20261019` 的 189 个绩效日导致大量上游请求，实际测试超过 180 秒未完成。Meridian 当前已有支持指数的区间未复权日线接口，不再需要此旧实现。
2. 交易质量逐页读取订单/成交/费用，每页都带排序及 OFFSET；费用最多只有 4 页、共 20,000 行。测试账户实际有 38,674 条订单、38,576 条成交和 35,703 条费用，旧接口约 74 秒后报错，而非正常返回完整质量结果。
3. 绩效序列对含原始报文的宽表做扫描；成交日期的普通/legacy 条件合在一个 OR，阻碍索引读取。旧执行计划为 4,537 ms，访问约 52,086 个缓冲页。
4. 前端虽先画曲线，仍等待七项明细全部结束后统一更新并解锁按钮；同时会重算已发布净值，而不是直接引用正式版本。

## 已发布改动

### 基准与序列

- 使用 Meridian `market/bars`：`security_id`、`start_date/end_date`、`frequency=1d`、`adjustment=none`。每次最多一个自然年、limit 1000；189 日区间一次请求完成。跨年长区间分块，不使用自行计算的行情，也不把缺失交易日补成零。
- 校验证券、日期范围、重复日期及截断；失败或非预期数据不当作有效基准。缺失日保留缺口，由 `benchmark_observation_days` 显示真实覆盖。
- 生产 schema 32 增加 close 持仓统计和普通/legacy 成交覆盖索引。已先以 `CREATE INDEX CONCURRENTLY` 在线创建、验证有效，再运行 migration 登记版本，没有停同步 worker 或锁住账本写入等待建索引。
- SQL 以互斥 `UNION ALL` 分离有交易日和无交易日的旧成交，legacy 仍按 Asia/Shanghai 时间计算日期；持仓聚合只物化一次。83 行原生快照结果与旧 SQL 全字段相等，合并已发布 NAV 后的 189 行 API 结果也完全相等。

### 交易质量

- PostgreSQL 专用读路径每张表只排序和读取一次，不再重复 OFFSET 翻页；费用只读取身份、时间、总额与完备性字段，不搬运整份原始费用报文。
- 保留原订单/成交扫描器、排序、日期、去重、ETF 划转排除、错误信息及质量规则。相同时间的费用仍按原 fee_record_id 顺序选择，不改变费用覆盖规则。
- 普通账户 API 分页契约不变。质量专用路径每类数据最多 200,000 行，读取额外一行检查溢出；超限或查询失败明确报错，不静默截断。原 Store 实现仍可使用旧分页接口。
- 最近一个月的交易质量结果除 `generated_at` 外与优化前完全相等；长区间现在能完整计算，真实历史告警仍保留，没有用删异常的方式加速。

### 页面加载

- 曲线返回即可再次查询；资金、已发布 NAV、归因、成本、交易质量和对账结果分别到达分别显示，不等最慢请求。
- 已发布当前版本从 `economic-nav` 读取，主指标引用原始 NAV 和持久化的 `pnl_components`，不产生新计算结果。仅当所选日没有可用当前版本时执行 preview；blocked 版本不绕过。
- 新查询取消被替代请求，账户/请求序号双重校验防止旧结果覆盖新账户。针对归因 singleflight，仍存活的读取者若遇到前一个读取者取消，最多重试一次只读计算，不继承取消后的半成品。
- 保留全部明细检查及权限门禁，前端发布版本更新为 `20261020-performance-read`。没有新增绩效结果的跨请求缓存，不会靠过期净值掩盖历史修复。

## 实测

测试账户债享5号，固定历史区间截至 2026-10-19，避免盘中数据变动干扰对比。秒数为单机内网本轮实测，不是延迟承诺。

| 查询 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 189 日净值序列，不带基准 | 首次 9.307 s，热读 0.230 s | 0.106 s |
| 189 日净值序列，带上证指数 | 超过 180 s 未完成 | 0.126 s |
| 相近一月的交易质量 | 首次 8.369 s，复测 4.227 s | 1.082 s |
| 年初以来完整交易质量 | 74.014 s 后 HTTP 500 | 3.819 s，完整返回 |
| 序列 SQL 执行计划 | 4,537 ms，宽表扫描 | 48 ms，覆盖索引读取 |
| 189 日曲线首绘 | 原基准请求未能完成 | 352 ms |
| 已发布主指标 | 等待整批明细 | 约 774 ms，质量请求暂停时仍可展示 |
| 带基准 CSV，189 行 | 同样经过旧基准慢路径 | 173 ms |

数据库冷热缓存会影响对比，特别是无基准序列；上表同时记录了旧热读结果，不能把所有增益都归因于代码或简单承诺百倍。

## 尚待优化

单日深度归因约 7.9 秒，成本 preview 约 16.2 秒，整个深度检查实测约 17.0 秒；这部分主要是大量日初/日终证券的行情、公司行为和成本复核，不再随所选区间逐日重算。539 个证券的完整检查保留，不为了首屏速度省略。

下一步考虑版本绑定的已发布成本/归因只读结果，让历史查看无需重新请求全部行情。必须绑定 NAV 版本、成本版本和行情来源，补费用、修历史或变更权威行情时明确失效；当前不使用“历史不会变”的永久缓存。

移动端交易终端已有 1280px 最小工作画布，本次不改其横向滚动布局，亦不冒称通过了无横向滚动的手机布局测试。
