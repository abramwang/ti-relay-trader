## 双账闭合方法

98,819条非零ETF实收实付，按“证券代码、实际净金额、资金款/佣金/过户费类别、重复次数”比较交割单与资金流水，完整多重集合相等，未匹配为0。不将重复金额去重，不把ETF成分划转伪装成普通成交。

交割单的日期并非每类记录都具有同一种语义，因此不能把所有交割日期都盲目作为成交源日：

- 29,302条现金记录的流水摘要明确给出源日期；其资金交割记录按记账日呈现，逐类逐日金额集合验证后，将现金权责从记账日回溯源日。
- 36,972条明确源日的成分过户费，交割单本来就在源日。逐日集合验证后保持原日，**不能再调整第二次**。
- 其余记录保留交割账日期，包括无父单编号的现金差额；只需完整金融集合闭合，不按金额相似度或“最近一天”补造逐笔身份。

```text
源日实收实付 = ETF交割账实付净额 + 明示现金源日调整（不重复移动已在源日的过户费）
期末ETF净应收应付 = 累计源日实收实付 - 累计实际记账净收付
经济资产 = 券商报告总资产
         + Meridian市值与原表市值之差
         + 已验证的真实分红时点调整
         + ETF净应收应付
当日盈亏 = 当日经济资产 - 上日经济资产 - 真实银证净流入 - 债券策略资本净流入
```

例如三笔4,229.40元现金差额在10月19日记账，交割账源日期是10月16日；16日记录应付，19日扣款时冲销，不把扣款再算19日亏损。已有明示源日期的正退款和负补款一并处理，不单看正收款。

截至导出日，两本账覆盖的实际净应收应付回转为0。这仅证明**已导出实际记录**闭合，不是券商出具的私有最终清算证明，也不证明未来不存在更正或尚未导出的事项。全序列保留该边界；不以IOPV、PCF或预计T+n日期补造现金。

这是事后以实际清算款回溯的会计序列，不代表原交易日当时就能看到未来退款，不能作为无前视偏差的策略实时输入。
