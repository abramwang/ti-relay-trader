## 1. 目标与交付边界

依据用户提供的《OC CTP 期货接入：阶段交付与 Relay 配合确认》，首次审阅的 OC 实现基线为 `dbd1e30`，使用指定 CTP `v6.7.13`。已交付配置、SDK 校验、认证登录状态机和四类查询原始结构收集；没有完成 Relay JSON 页、Redis 心跳、持久身份及交易闭环。当前程序仅开放 `--help/--check-config`，正常启动退出码为 3，不能替换在用交易服务。离线构建、5 个 CTest 和合成回调验证不等于真实柜台验收。

后续回复报告新增 `58dfa6b`（UserID/InvestorID 独立配置）和 `83ea49d`（显式单合约原始查询）。它们更新离线能力基线，不代表托管凭据、约束校验或 Stream 链路已经实现；上述运行边界不变。Relay 本轮未独立执行 OC 构建或在线验证。

本轮只做规划及文档更新；不修改交易代码、数据库、配置、生产权限，不切环境、不启动 CTP、不发送业务命令。原华鑫账户、A 股流程及未完成的历史绩效修复保持原状。

首期目标：独立 CTP 测试账户的普通期货查询、订单/成交持久化、限价报撤单、批量子单、SDK 回调和终端展示。按 OC 本次测评范围先验收 SHFE、投机交易；其他交易所逐项开放。已有 CFFEX 股指期货行情不代表 CFFEX 交易已具备能力。

首期不做期权、组合、条件单、市价单、自动平今/平昨拆单、自动换月、银期转账、模拟撮合或跨机器选主。期货结算与正式绩效另设阶段，不能把完成报撤单等同于账户会计闭合。

## 3. 对 OC 五项 P0 的建议答复

下列字段名和映射属于待确认设计，不应据此直接发送命令；F0 冻结后再交付可执行 fixture。

### A. 路由与凭据

- 接受沿用六类 Stream、`body` entry 和 `relay.stream.v1`；不另建一套期货消息总线。
- 建议本次采用 `broker_id=ctp_4900`，它是 Relay 路由标识。OC 最新回复说明期货公司通知明确给出原生 BrokerID `4900`，这是通知证据而非从路由推断，尚待真实登录验证。以后按实际期货公司分配路由，不能所有公司共用 `ctp`。
- 首期一个逻辑账户对应一个 gateway；`account_id/gateway_id` 由 Relay 显式分配。逻辑账户在同一环境内唯一，保持现有只传 account_id 的 API 无歧义；真实 InvestorID 不直接充当跨券商唯一键。TEST/PROD 数据库及配置继续隔离，账户到券商的绑定不可被静默改写。
- 测试账户实际标识等原生身份确认后分配。本轮不新建账户；若选择带前缀的逻辑 ID，须先扩展现有数字账号校验并验证凭据 AAD、路由、UI，不能直接把示例账号填入配置。
- BrokerID、InvestorID、UserID 分开保存；OC 已报告独立配置的离线实现，认证/登录使用 UserID、账户业务使用 InvestorID，不提供两者相等的默认值。真实身份关系仍需核实，不能使用猜测值上线。
- 建议复用现有加密信封、版本轮换和审计，密文内增加明确的凭据类型/结构版本，CTP 明文容纳原生身份、Password、AppID、AuthCode。精确 JSON 字段由 F0 冻结，不把 AuthCode 塞进华鑫 dynamic_password，也不改变已有华鑫凭据解密语义。
- 密钥选择按环境和券商路由，不回退到 HUAXIN 配置。密码、AppID、AuthCode 不进入命令、普通文档、页面响应或日志。新增凭据写入、登录、结算确认均需另行明确授权。

### B. 委托契约与校验

- 建议采用 OC 提议的 `business_type=F`、`trade_side=B/S`、`offset_type=O/C/CT/CY`、`hedge_type=speculation`。买卖方向和持仓多空分开解释；期货必须显式提供开平，不沿用股票省略值。
- 更正现有实现：华鑫 HTTP 与命令 payload 目前均使用 `price/qty`，订单回报常用 `limit_price/order_qty`。CTP 候选命令按 OC 提案采用后者，需新增显式适配而非声称已有转换；具体精确价格字符串方案见 F0 附录。既有华鑫链路不改，不增加平行 SDK 下单方法。
- 数量单位为手，必须正整数；价格按可信合约最小价位校验，使用精确十进制/整数档位比较，不用浮点余数误判。适用的合约有效期、数量限制和价格限制缺证据时返回未就绪，不凭股票规则猜测。
- `symbol` 保存完整原生 InstrumentID，大小写及长度原样保留；Meridian security_id 为显式映射，不靠统一大写/截断生成。连续、主连等研究代码不得当可交易合约直接发送。
- C/CT/CY 是否适用于某合约须由契约及样本确认。不能在拒单后自动换开平枚举，也不在 Relay 或 OC 自动拆平仓。
- 下单、订单及成交均携带开平和投机属性。幂等指纹必须覆盖新增经济字段及账户路由，不能让相同幂等键的开仓和平仓被视为同一请求。
- SDK 复用 submit/cancel/batch 及订单、成交回调，补充类型与 capability；未支持能力必须明确失败，不能只在 UI 隐藏。

### C. 持仓与资产

- 复用账户、命令、订单/成交及审计基础设施；建议增加期货类型化持仓/资产快照存储，不把全部股票账表重构为通用期货模型。
- 持仓业务维度至少为逻辑账户、交易所、合约、PosiDirection、HedgeFlag、PositionDate、InvestUnitID；快照存储另含 TradingDay、快照类型与采集批次/代际。明确返回的空 InvestUnitID 规范为 `""`，缺失/无法解析判不完整，不能同样补为空串；防止 NULL 唯一约束漏去重。
- 原始 Position/TodayPosition/YdPosition、冻结、成本、保证金均保留。今昨汇总基于已验证字段包含关系；Position 不是三个数量的简单相加，多空不是一行净持仓。
- 资金按 BrokerID、AccountID、CurrencyID、BizType 等原生范围保留全部行及 TradingDay、SettlementID、采集时间；范围不明时不跨行相加，不末行覆盖。AccountID 不由 InvestorID 拼接推导。
- 建议新增期货专用权益、可用、已用/冻结保证金、手续费、持仓/平仓盈亏字段。Balance 等标准投影必须取得实际回包和范围验证后确定；`cash_total/net_asset/market_value` 不先补成看似完整的数字。
- 合约名义价值可单独作风险展示，不加到净资产；保证金与已含权益的盈亏也不能再次叠加。失败查询不置零、不覆盖成功旧快照，不刷新旧数据时间；完整零行结果与查询失败分别处理。
- 公共 API 保留统一账户入口，按明确产品类型返回期货结构及 schema/capability，防止 SDK 或终端把期货默认为股票。具体嵌套结构、列表混合类型策略在 F0 冻结。

### D. 身份和交易日

- gateway_order_id 为发单前落盘的不可变逻辑身份。优先兼容扩展字符串原生编号字段，保留华鑫既有数值 order_id；CTP 的 OrderRef/OrderSysID 不强塞 int64。精确字段及 SDK 类型在 F0 一次冻结，未提供的旧字段不伪造为有效编号 0。
- 独立保留 RequestID、OrderRef、FrontID、SessionID、OrderSysID 与 counter_session_id。柜台会话和 OC 进程会话不是同一概念，重连不得据此重建另一笔逻辑订单。
- 采用 `native_ids` 对象作为待冻结方向；定长字符的空间填充、规范键编码与原始值分开定义并提供逐字节样例，不允许两端各自 trim。成交先到且无法关联时持久暂存/查询补齐，不捏造委托价或原始委托量建立假订单。
- 外部订单最终身份建议为账户路由、TradingDay、ExchangeID、OrderSysID；无 SysID 的事件用明确会话/OrderRef 暂存关联，空编号不合并。补齐身份时增加别名映射并归并到既有不可变订单，不通过换 gateway_order_id 生成第二笔。
- 成交原生去重键至少含账户路由、TradingDay、ExchangeID、TradeID，OrderSysID/合约作为一致性检查；重复键内容不同应进入冲突审计，不静默覆盖。最终键还需 OC M3/M4 样本验证，不能继承现有含 gateway_order_id 的键而放过别名变化后的重复成交。
- trade_date 使用已确认 CTP TradingDay；委托/成交自然时间另存带 +08:00 的时间戳，并区分源事件时间、接收时间和更新时间。夜盘不以接收日强制归日；缺真实自然日期不能直接用 TradingDay 拼时分秒，必须明确来源或标记未知。
- 委托准入需要新鲜、可用的柜台交易日；首次受理后冻结其关联，幂等重试不能跨午夜换交易日再发一单。历史查询按交易日，额外支持自然时间展示，不能套 A 股收盘自动终态化或 TEST 日期纠偏。

### E. 回执、恢复及费用边界

- 接受沿用 accepted/order_action_receipt、order.event、独立撤单结果和查询完整末页语义；不新增交易命令 final chunk。
- 批量是逐子单结果，不是原子事务；失败子单、拒撤、部分成交撤余、未知执行结果分别保留。未知结果不自动重报、重撤或按超时终态化。
- 就绪按 Redis、认证登录、结算确认、完整账本快照、合约元数据及本地权限逐层判断；任何必要条件未满足即拒绝新单。撤单能力独立判断，不机械绑定新单入口。结算确认不能因打开页面或定时器到点自动授权。
- 独立撤单门禁不绕过只读权限：`trading_enabled=false` 继续禁止下单和撤单。新单关闭但允许撤单须另有明确授权配置，且仍需账户登录、无歧义目标和柜台必要状态。OC 当前共用 canTrade 且快照未就绪，独立撤单尚未实现。
- 复用现有幂等、checkpoint、查询代际、DLQ、审计能力；OC ACK 必须落在持久结果或可恢复执行边界。重启重放只能恢复结果，不重复调用交易 SDK。
- 不把 OC 内部错误码直接加成业务枚举，不增加分布式选主或自动抢占。多进程竞争保持告警和人工处置。
- TradeField 不是最终逐笔手续费，账户 Commission 不均摊为已确认订单费用。未支持/待核验必须保留质量标记，不能填零或借用股票费率。

## 5. 任务与行情边界

- 每个账户明确交易产品及能力，A 股原有盘前、15:01 收盘采集、权威行情复算和华鑫 15:30 下线口径不变。期货按品种/交易日安排独立计划，不纳入现有股票任务默认账户集合。
- 期货有夜盘、日间分段和节假日边界；任务不能只把 A 股时钟平移，也不能自动假设前一自然日就是夜盘日期。时段和交易日依赖 Meridian 已公布契约及 OC 柜台事实，双方不一致时告警并保护交易准入。
- 延续已有原则：柜台最终资金/持仓/订单/成交采集不依赖行情可用；Meridian 故障延后估值，不丢交易事实。结算确认、数据采集和 Relay 绩效核算是三个不同操作。
- Meridian 负责行情、合约主数据、标准 security_id、最小价位、乘数、历史 bars/SSE 及可用的日历/结算价。需要补能力时提需求，不在 Relay 自建行情或自行推定 SHFE 覆盖。
- OC 单合约查询保留柜台静态约束，与 Meridian 元数据建立映射和一致性检查；InstrumentField/IsTrading 不证明账户专属交易权限或当前新单必能接受，也不包含动态涨跌停价。静态与动态约束分别核验来源及时效，冲突时不猜值放行。请求上下文的登录 TradingDay 不伪装为合约原生字段；缺行情或约束不停止柜台只读采集。
- 暂估行情 PnL 与柜台持仓盈亏、正式结算盈亏分列，说明时间及口径；期货数据不混入股票/ETF 成本账，也不直接加保证金/名义金额来修正权益。

## 6. 必测矩阵

| 类别 | 最小验收样例 |
