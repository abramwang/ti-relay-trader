## Relay 已对齐的语义

OC报告的当前资金映射为：

```text
cash_available = UsefulMoney
cash_total = UsefulMoney + FrozenCash + FrozenCommission
           + UnDeliveredFrozenCash + UnDeliveredFrozenCommission
net_asset = cash_total
market_value = 0
```

这是现有OC资金投影，不证明全账户现金范围，更不是产品会计净资产。Relay继续在派生读模型和结算中独立处理证券估值、逆回购应收及有证据的清算权益，不把FetchLimit再加到现金、不把Deposit/Withdraw无条件当成外部资金。

`fee_complete=true && association_complete=true` 只使该订单的柜台费用快照满足现有消费条件，不是券商最终交割证明。`fee_as_of` 是采集时间；不据其填充 `settled_at`，也不自动把NAV或ETF清算版本推进为finalized/confirmed。内部 `actual_fee` 与 `fee_coverage_complete` 分别表示观测金额和覆盖条件，不代表最终清算。

`adapter_context.component_fee_total` 是同一条费用记录的六个费用分项之和，不是篮子成分股所有订单费用之和。该审计字段不能与本记录 `total_fee` 再次相加，也不能因字段名含component就跨子单汇总。历史77.385与38.72的差额保持待核验，不减半、不补固定差值。

10月16日已恢复的387/388净值仍依据原有券商外部证据与版本化修复，不因本轮静态报告改变金额、撤销证据或宣称自动化已完成。后续未知资金不得由余额差、IOPV或PCF补造。

## 下一轮 OC 交付范围

下一次交付主体应是可运行的当前日只读取证实现和实际请求证据，不再仅是头文件清单。实现可以先作为独立诊断入口，不必先新增Redis动作或Relay接口。

### P0 资金回包行与范围

1. 保留 `ReqQryTradingAccount` 全部原始行及 `OwnerUnit` 等作用域字段、账户/币种/类型/采集时间和完成证明。修正末行覆盖限制；不同作用域未经证明不得求和或选末行充当全账户合计。
2. 完成 `ReqInquiryJZFund` 请求与非空回调处理，以明确配置的账户发只读请求，报告原始返回/回调错误、UsefulMoney/FetchLimit及与极速资金的包含关系。
3. 对 `ReqQryFundTransferDetail`、`ReqQryPeripheryFundTransferDetail` 实现有限当前日取证，保留方向、业务类型、状态/冲正、时间和稳定流水身份，不直接分类为产品外部入出金。

多行回包属于已经识别的实现限制；不能把“接口可调用”记成“资金范围已完整”。若当前协议无法表达经验证的范围，先交原始取证结果，再共同确定最小wire扩展。不能由Relay推断丢失行，也不能在缺少范围证据时发布伪全账户总额。

### P0 初始化查询的错误可观测性

保留SDK同步返回码，不统一吞为-1。对初始化订单查询被明确限流且能证明未发出的情况，设计有界退避、次数/时间截止和初始化ready门禁，保留每次请求身份及失败原因。未取得完整快照不能声称 `order_snapshot_ready=true`。

先用离线故障样例证明有界重试和门禁，再在允许的当前日只读窗口验证。不自动重发下单或撤单；对是否发出不明的查询不套用“未发出”的安全结论。本项是静态条件性风险，不追认成某次生产故障的已证实原因。

### P1 新版 ETF 与逆回购能力取证

- `ReqQryPublicOfferedFundTradeDetail`：先向厂商/券商明确ManagerID规则及普通投资者权限，不猜填投资者账户。取得样本后区分ETF/成分/资金替代/交收/冲正，保留DataIndex及父订单关系；总替代金额与分市场分项不能重复相加。TradeTime不当作资金记账时间。
- `ReqQryPrematurityRepoOrder`：只读检查未到期记录的可见范围，不能把“能查未到期”推广为“已取得返本付息流水”。
- `ReqQryOrderFundDetail`：原样保留同笔费用快照及父子身份，解释六分项算式和最终交割差异；金额差异未闭合前继续标记最终性unverified。
- `ReqQryPublicOfferedFundOrderDetail`：当前头文件无声明，不接入、不补声明、不向Relay提出接口需求。

ManagerID规则或账户权限暂时不明确时，P1可明确标记unverified，不应阻止先交付P0的可运行取证工具。
