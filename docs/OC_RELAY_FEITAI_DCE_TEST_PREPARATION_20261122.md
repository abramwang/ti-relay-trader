## 4. 无行情柜台的定价

本轮不让“全天可测试”反过来依赖交易时段才有的新鲜行情，也不造一份 Meridian/CTP 行情快照来满足原门禁。

- **常规/生产路径不变**：策略委托价由 Relay 结合 Meridian 处理，OC 原价原量转发，柜台最终判断；飞泰例外不能传入生产账户或普通策略接口。
- **飞泰 TEST 路径待接线**：由操作者/测试用例显式给出合约、方向、开平、手数和合法限价。价格来源记录为测试输入，不标成实时行情或真实最佳买卖价；可参考真实 Meridian/外部行情，但保留其原始日期和采样时刻，不伪称与测试柜台同步。
- 合约原生代码/交易所/tick 等取已核实的主数据或柜台事实，不能猜某个 DCE 合约今天仍可交易；记录柜台支持的合约及限价要求。没有深度行情时不生成涨跌停/买卖一，也不把同前缀期权混为目标期货。
- 接线不依赖每笔 `ReqQryDepthMarketData`，显式事实查询无结果仍如实返回失败/缺项。若测试服务另有价格限制，以实际说明/回包核验，不为凑通过自动改价、减量、换合约或换账号。

当前仍缺**一个本柜台实际可用的 DCE 普通期货合约及合法测试限价依据**。可由 OC 在后续获准只读窗口查询并反馈必要事实，或由期货公司给定；无需先向 Meridian 提新功能，也不要求 OC 跟 Meridian 对接。

## 5. 测试矩阵与判定

下表期待来自用户转交的柜台规则，并非本轮实测结果。每单有独立登记/幂等/订单身份，命令受理、订单状态及真实成交分别核对；价格、方向、开平和具体合约尚待确定。

| 手数 | 柜台说明 | Relay 验收与后续显式动作 |
| --- | --- | --- |
| 2 | 已报 | 核对真实工作态、原手数与本地关联；可撤时发对应撤单，必须有撤成事件，不能以 accepted 代替 |
| 5 | 部成 | 累计真实成交大于 0 且小于 5；不猜具体成交数。对实际剩余量撤单，核对最终累计成交、撤余和成交去重，不以剩余量再补新单 |
| 3 | 市场状态 | 原描述不足以预先认定错误码或终态。记录同步返回/异步错误/订单状态及原文，由实际回包确定；不能凭手数伪造 rejected 或认定柜台整体不可用 |
| 10 | 资金不足 | 核对柜台实际错误及发生阶段，保留原值；这是测试触发场景，不据此认定查询资产错误、账户真缺资金或永久关闭账户 |
| 其他合法手数，本轮建议 1 | 完全成交 | 核对真实订单终态与逐笔成交合计，不以 0/负数等非法数量解释“其他手数”；成交形成真实测试持仓，不自动反向平仓 |

建议先完成 2 手报撤，再做 5 手部成撤余，之后分别检查 3 手/10 手场景及错误后合法命令继续，最后核对成交/持仓。错误后的控制单由 Relay 显式发送，不由 OC 自行发探测单。**不需要逐笔重新建设审批流程或 OC 次数门禁；具体批次仍在用户明确的 TEST 授权范围内执行。**

若实际结果与数量规则不一致，保留事实并暂停该场景核对，不重复报单凑预期。若本地校验挡住了测试，记为“未到柜台”，不冒称资金不足/市场状态用例已通过。成交、撤单竞态或执行未知不以新 ID 自动补测；测试结束汇总全部活动单、成交及仓位，是否清仓由用户决定。

这些场景可以证明通用转发、部分成交和失败后继续等能力，但不能证明真实行情撮合质量、CFFEX 生产资金/保证金、实际市场时段或全部开平规则。券商最终验收口径及报告要求仍由其确认。
