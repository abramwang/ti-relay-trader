日期：2026-11-21，Asia/Shanghai。发送方：Relay；接收方：OC。
依据：用户转交《OC 致 Relay：生产待办与每日启停安排》，OC 实现 `053ded1`、安排 `3bb2c37`；Relay 源码核对基线 `5e3bc07`。

## 1. 结论与本轮边界

**安排一致，可以按此推进，无需再回签原则。采用盘前 cron 启动、日盘常驻、盘后 SIGTERM、次日新进程。** 原 state、路由、source、epoch、接收位点和防重责任延续，不每日清库。始终不断线的进程内 TradingDay 切换移出本期上线前置；已有实现和回归保留。仍验收盘中断连、次日持仓/结算和旧输出续收，不增加夜盘。

现在还不能认定“只差部署”：OC 正式生产入口及必要累计容量未完成；Relay 的生产发送、每日新会话衔接及完整风险入口也未完成。排队命令过期是双方共同缺口，不因 OC 删除固定五秒检查而自动解决。

本回执只同步进度、分工和开发顺序，不授权部署、切环境、初始化、登录、查询、结算确认或交易。没有安装 cron、清理状态或改线上权限。下方新增计划均不是已经实现的能力。

## 3. 首发业务范围

本轮开发和验收基线取**一个明确账户、CFFEX 目标普通期货、日盘、单笔限价报单和单笔撤单、投机、B/S 与普通 O/C**。当前已有股指 IF/IH/IC/IM 策略配置；实际合约及账户权限按后续确认的官方环境落实。这里是首发范围，不是通用 CTP 编码的交易所白名单。

- **批量不列为本轮前置，OC 先不接批量。** 多笔独立单可以顺序执行，不冒充原子批量。若 Chronos 上线策略必须使用批量接口，再显式增项，不将尚未接线的接口交给策略使用。
- Relay 普通 C 使用完整、当前会话持仓查询，按方向计算持仓减柜台冻结、未完成本地预留和查询后已平量；登记/预留同事务，发送前复核。未知发送不释放，失败的新查询不回退旧成功快照。
- 今仓/剩余昨仓可读，不等于 CT/CY 分桶可用；分桶平仓、跨会话活动预留承接、外部交易覆盖及明确拒撤后的新尝试仍有缺项。不能把 OC 的 O/C/CT/CY 编码支持当成 Relay 风险验收完成，也不将 CT/CY 静默改为 C。
- 当前真实成交证据仍主要是 SHFE 买开；CFFEX 买卖开平、部分成交撤余、拒单/拒撤后继续和跨日持仓须在线补验。资金/保证金规则尚未闭合，生产仍不放行。
- 原生查询完成不等于标准业务页完整。外部空 SysID/无法标准化的行保留原值及失败，不丢行后标成功；尚未交到 Relay 的原文单列交付缺口，OC 本地日志不算 Relay 已持久接收。复用现有出口补齐必要事实，不把每日人工传审计文件作为运行条件。
- 各发送入口归并 Relay 同一策略、日历和风险判断；停止新单与合法撤单分开。OC 不选择价格、调整手数、隐式查询行情或重复审批。

## 4. 每日生命周期与收件

以下为**工程候选时间关系，待官方环境和目标品种确定后填写绝对钟点**，不是已安装任务。`T_open`/`T_close` 为 Relay 已配置且核实的目标产品日盘起止；多个产品取最早开始、最晚结束。所有时刻使用 Asia/Shanghai，不直接套用华鑫的停机钟点。

| 阶段 | 候选安排 | 双方执行边界 |
| --- | --- | --- |
| 启动准备 | `T_open - 45分钟`，并与官方前置可用时间校准 | OC 单实例启动，真实登录得到 TradingDay；Relay 独立接收服务先就位，检查真实来源、epoch 和原位点。登录失败不伪造当日状态 |
| 盘前初始化 | 目标 `T_open - 10分钟` 前形成结果 | Relay 记录新 session/代次，使旧准入事实失效；按实际需要登记新查询。结算依据明确的账户/交易日决策，不因登录或工作日 cron 自动批准 |
| 日盘/午休 | 进程保持常驻 | Relay 依目标时段/日历控制新单与撤单，OC 只执行收到的有效请求。短断连恢复后重新核对上下文；旧输出继续按原命令归属处理 |
| 收盘与尾部采集 | 各产品时段结束即停止其新报单；`T_close + 1..10分钟` 采集资金/持仓/订单/成交 | 撤单仅在仍获允许且目标有效时发送，不自动撤单/平仓。采集不依赖 Meridian 日线就绪；后续估值另行等待行情，不能拖住现金和持仓保存 |
| OC 计划停机 | 候选 `T_close + 30分钟`，为查询及尾包留缓冲 | stop 核实准确 PID 后 SIGTERM，保留未知和未交付。采集失败告警，不伪造成功或静默延长/重启；查询完成也不是账户无风险的证明 |
| Relay 尾包与次日 | 停机后继续收件至少 5 分钟；接收服务可继续常驻 | 持久保存原文/位点，停机不清 owner；仍有未决则单列。次日续接原流，不从 0 或 `$` 重新开始，不代 OC ACK |

Relay 的下一项实现是把**稳定的运输绑定**和**会变化的业务会话**分离：原路由/source/epoch/owner/cursor 不随 OC 日启重建，新会话另行登记，旧查询不能完成新请求，旧事件不能把当日 ready 置真。新会话可读取不等于允许交易；旧未决、冻结与持仓不能因换日消失。新收件原文仍可长期保留，业务投影按原关联决定能否应用。

运维增加“计划停机/启动等待/盘中失联”的独立状态：计划停机只改变连接告警分类，不隐藏实际陈旧时间、未决命令、收件积压或存储错误。当前证券的非监控时段不能自动覆盖期货，期货日历未知时不猜休市。

**不为 CTP 联调停止生产链路。** 复用独立 TEST 接收程序、专用配置/连接变量和库；后续 TEST 发送/观察入口也必须明确隔离。当前主站仍生产，完整并行部署尚待实施，本回执不执行环境切换或启动测试服务。

## 5. 命令有效期与结算

### 命令有效期的最小共同增量

现状：Relay 的本地 approval/发布 Lua 有时限检查，但没有形成传到 OC 并在排队出队前执行的完整过期契约。OC 已报告移除自行定义的固定五秒规则。**不能声称目前已发布的命令必然在五秒后失效。**

下一项由 Relay 提供小型字段补充和共享用例，OC 只按明确命令字段执行，不新增业务审批。以下是拟定语义，尚未冻结 wire 字段位置、版本或默认秒数，不向旧部署直接发送新字段：

1. 有效期由 Relay 按动作/策略配置确定并绑定原命令；不是行情年龄、心跳年龄、进程时长，也不是每日授权时段。无共同支持的部署不能假称存在队列过期保障。
2. OC 在尚未进入可能调用 SDK 的执行阶段检查期限；只有能证明未调用 SDK，才能持久返回“过期未执行”，随后按现有输出确认/ACK 流程完成。到期与 dispatch 的竞态须有明确原始记录。
3. 已进入 dispatch、SDK 返回未知或输出发布未知的责任不能事后改为“过期未执行”；不回滚订单状态，不自动重报或换 ID。重投已登记命令继续恢复原结果，修改期限不能取得第二次执行资格。
4. 撤单有独立期限和权限；报单行情过期/停止新单不能直接关撤单。命令过期不等于原委托撤成。查询超时、迟到回包仍按原查询关联，不能覆盖新请求。
5. 共享用例覆盖排队至到期、临界时刻、恢复后过期、重复/改期冲突、发布未知及撤单独立。字段/幂等绑定和时钟异常处理一并确认后实施，不重做整个 F0 矩阵。

### 按日结算

沿用既有 OC 按账户/TradingDay 保存的确认记录和已约定配置/操作入口。Relay 决定是否对指定交易日确认，OC 负责真实执行和回传；成功或未知不因重启重复。正常配置省略硬编码 `execution.trade_date`，实际日取登录事实。**省略日期不是每日结算授权。**

Relay 还需补决策审计、当日状态核验和失败/未知展示，当前不声称已有全自动每日触发链路。先沿现有明确操作方式完成联测，不要求 OC 另造审批服务或新结算命令。
