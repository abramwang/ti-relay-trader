# SHFE 行情与交易准入边界修正

日期：2026-11-04，Asia/Shanghai。依据用户最新明确指示：Meridian只负责行情，直接推进SHFE接入；不能让交易API的ReqQryInstrument成为行情开发卡点。本文件优先于此前将exchange_full Trader样本绑定到SHFE行情发布的规划。

## 纠正的依赖

撤销“先取得CTP Trader API完整合约快照，再允许Meridian发布SHFE目录/行情”的统一前置条件。此前Relay将行情目录质量与交易准入绑定过紧，需要由Relay纠正，不把依赖转嫁给OC。

用户确认CFFEX实时行情已长期运行，继续复用Meridian已有CTP行情基础设施；不要求重新证明CFFEX能否接入，也不因此认定SHFE已经验收。SHFE的新增覆盖仍按实际交付核验。

| 责任方 | 职责 | 不作为其前置要求 |
| --- | --- | --- |
| Meridian | 标准security_id与原码映射、行情合约目录、交易所公开参数、快照/SSE/bars、动态价格范围及日历/夜盘/结算数据质量 | 不必提供交易账户登录、ReqQryInstrument全量结果、账户可交易权限或下单量边界才能发布行情 |
| OC | 柜台原始身份和交易事实、交易会话、柜台合约静态约束及其来源/时效、报撤查询链路 | 不对接Meridian、不为行情服务实现全市场扫描，不把InstrumentField等同账户权限 |
| Relay | 复用Meridian标准，协调差异、行情展示及消费验收，结合OC约束与独立权限实现交易准入 | 不自建行情目录，不用行情已就绪推导交易已获授权 |

## Meridian 可以继续的路径

1. 按已有交易所权威资料及行情源建立/发布SHFE行情目录，保留原码、乘数、价位、生命周期的来源与质量；不因缺柜台委托量而阻断行情目录。
2. 无来源的柜台参数保持缺失/null及可解释的质量标记，不补默认值。目录可供行情使用与交易准入是否完备分开表达；具体字段继续采用Meridian既有契约，必要变化由其正式发布。
3. 在已有行情基础设施上分阶段推进SHFE快照/SSE、日夜盘时间及跨午夜、分钟完整性、历史/结算。每项仍核对覆盖、时间、stale、动态限价及来源，不要求等待另一项无关交易能力。
4. 直接行情链路及交易所原始事实足够时，不再要求额外获取交易账户凭据或Trader登录。用户已交由Meridian推进开发；本次Relay没有代为登录、订阅、重启或调整其服务。

SHFE官网Shadow可以作为Meridian评估行情目录发布的权威来源；本文件不直接将现有Shadow改成生产目录，也不声称其已完成发布。发布仍由Meridian按行情质量门禁执行，不能绕过身份冲突、来源、交易日或内容完整性检查。

## 既有 v2 整改如何保留

M1/M2/V1/V2的离线验收不撤销。它们保证的是**选择采用Trader快照时**的输入完整性和请求隔离，不是所有行情目录必须经过的来源。

如果将来使用该可选输入，exchange_full、真实request_id/connection_generation/IsLast、行数和原始字段仍须真实完整，不允许把单合约查询包装成全量。没有这类输入，不应把整个SHFE行情项目标为阻塞；行情可以使用经核验的其他权威来源。

原“M3 pending_authorized_sample”不再作为行情开发的总状态，改为按目录、快照/SSE、夜盘、分钟/历史/结算各自记录实施与验收进度。Trader采样仅在确有交易侧或补充元数据用途时另列可选事项。
