## 1. 本轮实现

在 `tests/ctpcontract/query_sequence.py` 增加离线、有界、单查询参考状态机，复用四类查询页 schema 和单页语义校验。它不连接 Redis/数据库，不发送查询，不存储生产原始证据，不执行 ACK，不发布或覆盖账本。

输入必须携带调用方预先登记的可信查询上下文：环境/券商/账户/Gateway、命令 message_id、action、ticket、SDK 请求号（未发出时 null）、查询会话、真实连接代次、TradingDay。实际部署如何登记这些证据仍待设计，不能从第一条收到的回包反推可信上下文。SDK 未发出和已发出不能混为同一个成功候选。

时间预算使用调用方提供的单调时钟，与自然时间及夜盘 TradingDay 分开；不能以 produced_at 代替本地等待期限。参考默认最多256页、100000行、8MiB报文体，均可构造时配置，属于本地测试资源界限，不是给 OC 新增的 wire 承诺。

## 2. 接收规则

| 场景 | 候选结果 |
| --- | --- |
| 索引0至N全部存在，只有N为成功末页，字段/证据/跨页业务键均通过 | ready，提供按索引排列的独立行副本 |
| 末页先到或中间缺页 | collecting；不返回部分结果、不替换旧快照 |
| 到达期限仍缺页/缺末页 | expired；迟到页不能复活该查询 |
| 同message_id、同原始UTF-8报文体重投 | replayed；不增加页/行/字节计数，不改变failed等状态 |
| 同message_id报文体不同，包括重新序列化改变空白/键顺序 | invalid；保留原文差异，不自行判断为同一次可靠输出 |
| 同页索引换message_id再发，即使行内容相同 | invalid；不能冒充原输出重投 |
| 两个不同成功终态、末页之后还有更大索引 | invalid |
| partial后failed且没有成功终态 | failed；不把部分行作为完整结果 |
| 成功与失败终态同时出现，包括末页先到但尚未收齐 | invalid；不按最后到达者覆盖 |
| 跨页出现相同业务键，包括相同行重复 | invalid；不静默去重来掩盖分页或范围错误 |
| 不同路由/原命令回包 | 拒绝，不污染本候选；真实分发层必须另保留审计 |
| 同路由和命令但ticket/连接/会话/SDK号/交易日不符 | invalid；不拼接旧连接或其他采样 |
| 调用方通知断线、代次变化或撤销本次采样 | interrupted；不自动重发查询或继续旧队列 |
| 超行数/页数/字节数、非法相关报文 | invalid；不输出截断成功结果 |

原始体相同仅指 `body` 字节相同，Redis entry ID 不参与重投身份。JSON解析仍拒绝重复键、非法常量及整数类型漂移；原始审计不能为了去重而重写。字节一致重投规则是待统一稿确认的保守候选，尚未以此拒绝线上 OC 回包。

四类跨页键沿用字段附录：资金保留全部作用域、持仓保留多空/今昨/投资单元、订单按TradingDay及gateway_order_id、成交按既有确定性fill_id。空持仓/订单/成交完整页允许返回空集合；资金空结果必须失败，不能清零。不同币种不合计，原生编号和时间不改写。

旧 `query_cases.json` 的 `terminal_count=2` 指不同终态证据或非原文重投，不包含同一消息原文再次投递。本轮不改原六份共享JSON，也不改变现有A股查询中断恢复口径。

## 3. ready 不等于已落库

参考模型在收到完整结果后可返回ready；如果后续收到冲突证据，会撤销当前候选资格，但不能撤销已经被外部代码取得的副本，更不能假装回滚数据库。生产实现必须另外持久保存消息身份、批次证据、发布状态和异常记录，验证代次/请求仍有效，并在事务内发布。

晚到矛盾消息不能静默覆盖既有账本，也不能自动删除券商事实；需要保存冲突、阻断该批次继续发布并触发核查。已发布批次如何标记及修复是后续持久化设计事项。本模型没有提供commit/ACK方法，不能直接当生产消费者使用。

重复投递不会延长期限；已经及时完成的查询不会因后来重复投递超过原截止时间而变成超时。失败查询的旧partial原文重投不会把failed改回collecting。断线处理必须由调用方显式通知，参考模型不读取真实心跳。
