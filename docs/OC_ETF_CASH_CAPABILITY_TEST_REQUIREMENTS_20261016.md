# OC 资金范围与 ETF 清算只读能力测试需求

日期：2026-10-16，全部业务时间 Asia/Shanghai。

2026-10-19进展：OC已反馈SDK兼容和静态能力复核，尚无账户业务查询样本或新只读取证工具。费用语义、多行资金回包限制及下一轮P0/P1交付已明确在 [Relay反馈与验收安排](OC_CASH_CAPABILITY_FEEDBACK_RESPONSE_20261019.md)；本需求的在线验收尚未通过。

## 目标与边界

请 OC 验证华鑫交易 API 能否提供足以支持账户绩效的最小资金事实，并提交能力测试报告。不是要求 OC 实现 Relay 的绩效算法，也不要求 OC 提供券商客户端那样的完整历史资金流水。

- 只读查询、已有日志/回包分析及离线单测即可，不需要为了验收下单、申赎、转账或重启生产。
- OC 只负责当前交易日。下文10月9日案例是已获券商证据的历史对照样本，不能要求当前 OC 查询到这些历史数据。
- 接口声明、返回成功和字段非空都不等于覆盖完整。无法查询、权限不足或字段含义不明，应明确报告，不用余额差额补造记录。
- 本轮先核实能力，不预先变更 `relay.stream.v1`。新增可交付事实的 wire 字段再与 Relay 确认，原始审计字段不能被推断结果覆盖。

## P0：全账户资金范围

本地参考 SDK `/home/Titans/resource/drivers/huaxin/include/trade/` 存在以下入口。请以 OC 实际部署 SDK 和账户权限为准核实，不必为不可用接口做复杂兼容。

| 入口 | 测试内容 | 交付说明 |
| --- | --- | --- |
| `ReqQryTradingAccount` / `OnRspQryTradingAccount` | 保存同一次回包的 `AccountID/AccountType/PreDeposit/UsefulMoney/FetchLimit/Deposit/Withdraw/FrozenCash/FrozenCommission/Commission` | 逐字段说明极速/普通柜台范围，是否为余额或累计发生额，冻结与手续费是否已包含 |
| `ReqInquiryJZFund` / `OnRspInquiryJZFund` | 对同资金账户查询集中交易系统的 `UsefulMoney/FetchLimit`，保留请求返回码和回调错误码 | 是否有权限、是否覆盖普通柜台；与极速资金是独立、重叠还是总分关系 |
| `ReqQryFundTransferDetail` / `OnRspQryFundTransferDetail` | 查询当前日内部资金转移 | 实际支持的方向、金额、状态、时间、流水号及覆盖范围 |
| `ReqQryPeripheryFundTransferDetail` / 对应回调 | 查询当前日外围资金转移 | 能否区别银行出入金与极速/普通内部划转；不能仅凭接口名称认定 |

重点回答：

1. 现有 Relay `cash_total/cash_available/net_asset` 分别来自哪个原始字段/算式，是否只包含极速柜台；`net_asset` 是否实际只是资金，不含证券。
2. 同一时点是否可以获得普通加极速的完整现金，且不存在重复统计；若只能取得可用/可取，明确缺少哪些冻结、预扣或未交收分项。不能直接相加可用和可取。
3. `Deposit/Withdraw` 是否会包含内部划转、申赎清算、逆回购到期等非产品外部资金事项；能否给出原始业务类型。
4. 申赎预记现金、替代现金、退款、应付现金差额是否已进入现有资金字段，分别在什么阶段变化；能否区分“已包含”与“尚未到账”。
5. 逆回购本金何时从现金扣减、何时返还，是否有冻结/其他资产分项，真实净利息是否可区分。不要把 `总资产-现金-证券市值` 无条件归为逆回购本金。

测试过程中如自然发生内部划转、逆回购或申赎，保存前后只读样本即可；不能擅自执行资金动作。跨柜台查询非原子时，记录各自采集时刻和期间变动，不能声称是同一原子快照。

另一个待解释样本：387的10月12日券商资金表总资产 `49319698.84`、客户资金 `48806904.43`、证券市值 `257977.20`，差值为 `254817.21`；但当天真实逆回购本金只有 `253000.00`。多出的 `1817.21` 恰与后续现金差额扣款同额。请核实是冻结/预扣/待交收或其他范围差异，不能按相等关系猜其性质。Relay已单独保留该分项，没有当成逆回购本金；12/13日的证券归因残差仍保留，未抹为0。

## P0：ETF 清算事实是否存在可查询渠道

对普通成交、申赎父订单、成分划转、资金查询分别检查原始字段，不把 `turnover` 名称直接等同于已到账现金。

| 必要事实 | 希望验证的最小能力 |
| --- | --- |
| 同日赎回替代现金 | 实际金额、来源订单/ETF、是否已包含在资金快照及原始证据 |
| 跨日替代现金退款/补款 | 当前记账日的真实收付，能否关联原申赎日、ETF、批次 |
| 实际现金差额扣/付款 | 正负方向、记账时刻、源申赎关系；不能拿 PCF 预计现金代替到账 |
| 待结清权益 | 是否有权威应收/应付余额、分期与最终完成标志；没有则报告 unsupported |

若交易 API 不提供，请明确“哪些事实不可取得”，并反馈是否知道券商另有获授权的自动清算/资产汇总渠道。文件/API/SFTP 等均须先核实，不能承诺已有。每批汇总足以唯一闭合时，不强求每只成分股票的全部退款明细。

Meridian 继续负责公开 PCF、IOPV 和行情，不负责推断投资者私有清算款。跨日回款不能根据余额差、IOPV 或预计 T+n 日期直接生成。

## 报告格式与验收

建议反馈文件 `OC_RELAY_CASH_CAPABILITY_TEST_REPORT_YYYYMMDD.md`，至少包含：

1. OC 提交/SDK版本、环境、账户、交易日、查询时间及唯一请求ID；请求返回码、回调错误、末页/完成证明。
2. 每项能力标注 `supported / permission_denied / unsupported / unverified`；明确空结果和未完成/不支持不同。
3. 脱敏原始回包、原始字段到 Relay 标准字段的映射与包含关系，不输出密码、动态密码或密钥。
4. 有限只读查询重复结果是否稳定，重连后是否可重取；真实流水身份如何稳定去重、如何表达更正，源交易日与实际记账日如何区分。
5. 哪些输入在15:01、15:30前或更晚才可取得；若 OC 15:30计划关停后才发生清算，请说明无法通过当前进程获得，不要求为此延长生产交易进程。
6. 可交付的最小新增事实及仍不可见的边界。若不能支持，给出限制证据即可，由 Relay 与券商决定是否需要独立只读盘后渠道。

成功标准是查清资金范围和可用事实，不是“接口均返回200”。Relay 保持当日暂估与最终清算分层，并继续保留缺证据的质量标记；不会要求 OC 通过推断来消除阻断。
